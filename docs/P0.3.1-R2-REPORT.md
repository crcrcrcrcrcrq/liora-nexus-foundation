```
MagicLinkForm → signInWithOtp() → e-mail → /powrot?token_hash=…
  → establishSession() [server fn]
  → @supabase/ssr createServerClient (cookies HttpOnly)
  → requireSupabaseSession() → supabase.auth.getUser()
  → RLS: profiles / user_roles → fetchIdentity() → IdentityProvider
```

  **zero importów**, brak użycia runtime. Pozostawiony bez zmian (§10).

## 6. HTTPS Cookie Verification

```
Cookie: sb-<ref>-auth-token
HttpOnly: NOT VERIFIED
Secure:   NOT VERIFIED
SameSite: NOT VERIFIED
Path:     NOT VERIFIED
```

Powód: bez powiązanego backendu nie da się ustanowić realnej sesji, więc żadne
ciasteczko sesji nie powstaje. Zaobserwowano natomiast, że wejście na
`/powrot?token_hash=<nieprawidłowy>` przez HTTPS **nie ustawia żadnego
ciasteczka** i kończy się komunikatem o wygaśnięciu klucza (PASS dla ścieżki
błędu).

Konfiguracja w kodzie (dowód niewystarczający wg §5, podano informacyjnie):
`httpOnly: true`, `secure: isSecureRequest()`, `sameSite: "lax"`, `path: "/"`.
