# Internationalization (i18n) — LIORA

Jeden system tłumaczeń: **i18next + react-i18next**. Nie dodajemy drugiego mechanizmu.

## Struktura

```text
src/config/i18n.ts        inicjalizacja i18next (jedyna), lista języków, tagi lang/og
src/lib/i18n.ts           translate() poza Reactem + helpery routingu (/pl, /en, hreflang)
src/hooks/useLanguage.ts  jedyny punkt dostępu w komponentach: { t, language, setLanguage, ... }
src/components/i18n/LanguageSwitcher.tsx  gotowy przełącznik (jeszcze niemontowany)
src/locales/pl/<namespace>.ts   źródło prawdy (język polski)
src/locales/en/<namespace>.ts   lustrzana struktura EN (placeholdery `[EN] …`)
src/locales/pl/index.ts         scala przestrzenie nazw i eksportuje typ `Dictionary`
src/locales/en/index.ts         `const en: Dictionary` — typ pilnuje kompletności kluczy
```

Przestrzenie nazw: `common`, `nav`, `seo`, `layout`, `landing`, `about`, `services`,
`rituals`, `faq`, `locations`, `blog`, `contact`, `legal`, `booking`, `tarot`,
`astrology`, `auth`, `chronicle`, `admin`, `forms`, `states`, `errors`.

## Klucze

- czytelne, po angielsku, w notacji `namespace.obszar.element`,
  np. `landing.hero.title`, `tarot.shuffle.button`, `admin.sidebar.dashboard`;
- nigdy tekst jako klucz, nigdy numeracja (`key1`, `key2`);
- liczba mnoga i zmienne przez interpolację i18next: `t("tarot.remaining", { count })`.

## Użycie

```tsx
import { useLanguage } from "@/hooks/useLanguage";

const { t } = useLanguage();
<h1>{t("landing.hero.title")}</h1>;
```

Poza drzewem Reacta (route `head()`, JSON-LD, sitemap, serwisy):

```ts
import { translate as t, alternateLinks } from "@/lib/i18n";

head: () => ({
  meta: buildMeta({ title: t("seo.tarot.title"), description: t("seo.tarot.description"), path: "/tarot" }),
  links: [{ rel: "canonical", href: "/tarot" }, ...alternateLinks("/tarot")],
});
```

## Dodawanie nowego tłumaczenia

1. Dodaj klucz w `src/locales/pl/<namespace>.ts`.
2. Dodaj ten sam klucz w `src/locales/en/<namespace>.ts` (TypeScript zgłosi brak).
3. Użyj `t("namespace.klucz")` w komponencie — bez hardcoded stringów.

## Dodawanie nowego języka

1. Skopiuj `src/locales/en/` do `src/locales/<kod>/` i przetłumacz wartości
   (typ `Dictionary` pilnuje kompletności).
2. Dopisz kod do `SUPPORTED_LANGUAGES` i `LANGUAGE_TAGS` w `src/config/i18n.ts`
   oraz do `resources` w tym samym pliku.
3. `hreflang`, sitemap i przełącznik języka podchwycą nowy język automatycznie.

## Stan tłumaczenia EN

Struktura EN jest kompletna. Krótkie elementy interfejsu są przetłumaczone,
dłuższe treści mają placeholder `[EN] <tekst PL>` — wystarczy podmienić wartości,
bez ruszania kodu. Postęp: `rg -c "\[EN\]" src/locales/en`.

## Routing `/pl` i `/en`

Architektura jest gotowa, obecny UX niezmieniony:

- `LOCALE_PREFIX_ENABLED` w `src/lib/i18n.ts` (domyślnie `false`) sterują prefiksem
  w linkach kanonicznych, `hreflang` i sitemapie;
- `localeFromPathname`, `stripLocale`, `localizePath` obsługują adresy `/pl/...`, `/en/...`;
- włączenie: dodać trasę `$lang` w `src/routes/`, ustawić flagę na `true`
  i wywołać `setLanguage(localeFromPathname(pathname))` w `__root.tsx`.
